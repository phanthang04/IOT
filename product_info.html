Smart Door IoT – Detailed Documentation

1. Tổng quan dự án

  • Tên dự án: Smart Door Lock (ESP32‑CAM + PIR + Face + Palm + Servo)
  • Mục tiêu: Tạo một hệ thống mở cửa thông minh dựa trên nhận diện khuôn mặt và vân tay, có khả năng báo động chuyển động và tích hợp với server Python để quản lý, lưu trữ và gửi thông báo (Telegram).
  • Thiết bị chính: ESP32‑CAM (module camera), Servo MG90S, cảm biến PIR, module Wi‑Fi, nguồn 5V.

2. Kiến trúc hệ thống

[ESP32‑CAM Firmware] <-- HTTP/JSON --> [Python Flask Server] <-- DB (SQLite) <-- Web UI (HTML/JS)

Firmware (esp32_door.ino)

  • Quản lý camera, servo, PIR.
  • Cung cấp 2 server nội bộ: Port 81 (MJPEG stream) và Port 82 (REST API).
  • Gửi sự kiện (motion, face_ok, face_fail, palm_ok, palm_fail) tới Flask server.

Server (server.py)

  • Nhận POST/GET từ ESP32, lưu lịch sử, thực hiện nhận diện bằng OpenCV/DLib.
  • Cung cấp API cho UI.
  • Gửi thông báo Telegram khi có sự kiện quan trọng.

Web UI (index.html)

  • Dashboard dark‑mode, hiển thị video stream, trạng thái cửa, lịch sử.
  • Điều khiển mở/đóng, bật/tắt auto detect.

3. Luồng xử lý (Data Flow)

  1. Khởi động ESP32
    • Kết nối Wi‑Fi (cấu hình IP tĩnh).
    • Khởi tạo camera, servo và server nội bộ.
  2. Stream video
    • Client truy cập http://<ESP_IP>:81/stream.
  3. Phát hiện chuyển động
    • Khi PIR HIGH → ESP gửi GET tới SERVER/api/trigger_motion.
  4. Nhận diện khuôn mặt / vân tay (trên server)
    • Camera capture (/capture) → Server xử lý.
    • Face OK → trả về face_ok → ESP mở cửa.
    • Palm OK → trả về palm_ok → ESP mở cửa.
    • Fail → trả về *_fail → âm báo lỗi.
  5. Quản lý trạng thái
    • ESP giữ isAutoDetect và isCameraSleeping.
    • Không hoạt động >15s → camera ngủ.
  6. Đóng cửa tự động
    • Sau 3 s cửa tự động đóng.

4. Thuật toán chính

4.1 Motion detection (PIR)

if (digitalRead(PIR_PIN) == HIGH && (millis() - lastMotionTime >= motionCooldown)) {
    // Trigger motion event
}

motionCooldown = 10 s để tránh spam.

4.2 Face Recognition (Server side)

1. Load known_face_encodings from DB.
2. frame = cv2.imread(image)
3. face_locations = face_recognition.face_locations(frame)
4. encodings = face_recognition.face_encodings(frame, face_locations)
5. Compare with known_face_encodings using face_distance (threshold 0.45).
6. Return JSON {"event":"face_ok"} or {"event":"face_fail"}.

4.3 Palm (Hand) Recognition

Sử dụng mediapipe để trích xuất landmarks, tính toán góc các khớp, so sánh với mẫu. Độ lệch < 0.2 → palm_ok.

4.4 Camera Sleep/WAKE

Khi không có request trong cameraSleepDelay (15 s) → esp_camera_deinit() và đặt PWDN HIGH. Khi nhận bất kỳ request nào (stream, capture, motion) → bật lại camera.

6. Cài đặt & Chạy

  1. ESP32
    • Mở esp32_door.ino trong Arduino IDE.
    • Thay ssid, password và SERVER cho môi trường.
    • Upload.
  2. Server
    • Tạo virtualenv, pip install -r requirements.txt (flask, opencv‑python, dlib, mediapipe, python‑telegram‑bot).
    • Chạy python server.py → lắng nghe 0.0.0.0:5000.
  3. Web UI
    • Mở static/index.html trong trình duyệt (hoặc qua Flask static).
    • Kiểm tra stream, nhấn “Open/Close”.

7. Kiểm thử

  • Wi‑Fi: Serial prints WiFi OK: <IP>.
  • Stream: Truy cập <ESP_IP>:81/stream.
  • Motion: Khi có người qua, ESP gửi GET, server log “Motion trigger”.
  • Face: Đăng ký khuôn mặt (API /api/face_register), thử mở cửa.
  • Palm: Tương tự với API /api/palm_register.
  • Auto detect OFF: http://<ESP_IP>:82/auto_off → camera ngủ ngay.

8. FAQ – Câu hỏi thường gặp (để chuẩn bị demo)

Q1: Làm sao ESP biết địa chỉ IP server?

A: Địa chỉ server được hard‑code trong biến SERVER (line 36). Khi chuyển sang máy khác, cập nhật giá trị này và upload lại firmware.

Q2: Tại sao camera không stream được?

A: Kiểm tra:

  • ESP đã kết nối Wi‑Fi?
  • Port 81 chưa bị firewall chặn?
  • Đảm bảo setupCamera() thành công (Serial “Camera OK”).

Q3: Khi mở cửa nhưng servo không quay?

A: Kiểm tra PWM timer đã allocate (lines 384‑386) và chân SERVO_PIN (GPIO14). Đo điện áp trên chân servo hoặc thay nguồn.

Q4: Server không nhận được request motion?

A: Kiểm tra IP của ESP (Serial.println(WiFi.localIP())). Đảm bảo IP server reachable từ ESP (ping). Kiểm tra firewall trên máy chủ.

Q5: Face recognition luôn trả về FAIL?

A: Có thể vì:

  • known_face_encodings chưa có dữ liệu (chưa đăng ký).
  • Ánh sáng camera kém → ảnh mờ.
  • Ngưỡng 0.45 quá chặt, có thể tăng lên 0.5.

Q6: Tại sao camera ngủ quá sớm?

A: Tham số cameraSleepDelay ở esp32_door.ino (line 71) là 15000 ms. Có thể tăng lên 30000 ms.

Q7: Làm sao bật/tắt Auto Detect từ UI?

A: UI gọi endpoint /api/door/auto_on → server gửi GET tới http://<ESP_IP>:82/auto_on (bật) hoặc auto_off (tắt).

Q8: Khi demo muốn ghi lại log toàn bộ quá trình, có file log không?

A: Serial logs có thể xem trong Arduino IDE Serial Monitor. Đối với server, log được ghi vào server.log (cấu hình logging trong server.py).

Q9: Làm sao thay đổi chế độ IP tĩnh?

A: Sửa các giá trị local_IP, gateway, subnet, primaryDNS, secondaryDNS trong esp32_door.ino (lines 28‑34) và upload lại.

Q10: Nếu muốn mở rộng thêm tính năng (ví dụ RFID), quy trình?

A:

  • Thêm thư viện RFID, khai báo pin.
  • Tạo endpoint mới trên ESP (/rfid).
  • Server xử lý tương tự như face/palm.
  • Cập nhật UI để gửi request.

8. Risks & Challenges

  • Network instability: Wi‑Fi dropout can cause loss of video stream and delayed events.
  • Power supply constraints: ESP32‑CAM draws ~250 mA; insufficient power leads to brown‑outs, camera failures.
  • Latency: HTTP round‑trip (ESP → Server → UI) adds ~200‑300 ms; real‑time unlocking may feel slow.
  • Security: Hard‑coded SSID/password and lack of TLS expose the device to MITM attacks.
  • Resource limits: ESP32 flash (~4 MB) limits storing large models; recognition runs on server.
  • Hardware reliability: Servo jitter and PIR false positives can cause unintended door actions.
  • Scalability: Adding many ESP devices may overload the single‑thread Flask server without proper async handling.

9. Kết luận

  • Toàn bộ luồng từ cảm biến → ESP → Server → UI đã được mô tả chi tiết.
  • Các thuật toán nhận diện được triển khai trên server để giảm tải ESP.
  • Hệ thống có khả năng mở rộng (thêm RFID, Bluetooth, OTA updates).
  • Đảm bảo các tham số IP và cổng không xung đột, và luôn kiểm tra log khi gặp lỗi.
